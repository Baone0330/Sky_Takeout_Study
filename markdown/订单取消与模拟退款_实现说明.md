# 订单取消与模拟退款实现说明

日期：2026-10-26。基于当前原项目继续修改，保留新增的历史订单分页等已有代码。模拟支付开发配置继续开启，本轮不发生真实支付或退款。

## 一、实现后的业务规则

| 数据库原状态 | 用户操作 | 处理结果 |
|---|---|---|
| 待付款 `status=1 / pay_status=0` | 主动取消 | 写入已取消 `status=6`，保持未支付 `pay_status=0`，无需退款 |
| 待接单 `status=2 / pay_status=1` | 主动取消 | 在同一事务内写入已取消 `status=6`、已退款 `pay_status=2`；模拟全额退款 |
| 已接单 `status=3` | 点击取消 | 提示电话沟通，提供商家联系电话，不直接改订单 |
| 派送中 `status=4` | 点击取消 | 提示电话沟通，提供商家联系电话，不直接改订单 |
| 已完成 `status=5` | 调用取消 | 后端拒绝，保持原状态 |
| 已取消且 `pay_status=0/2` | 重复取消 | 返回首次结果，不重复更新、不重复模拟退款 |
| 状态组合异常或其他用户订单 | 调用取消 | 后端拒绝，不修改数据库 |

`pay_status=2` 表示本项目中的退款完成状态；本轮由模拟流程直接完成。不会请求微信退款接口，也不会产生真实资金流水。

## 二、后端如何保证数据库正确

入口保持为 `PUT /user/order/cancel/{id}`。不传额外参数时为用户主动取消；自动超时取消使用 `PUT /user/order/cancel/{id}?unpaidOnly=true`。

1. 原 JWT 拦截器校验登录，业务方法再次读取当前用户 ID。
2. 使用订单 ID、当前用户 ID 和 `FOR UPDATE` 查询订单。取消、支付及其他订单更新在同一行上串行处理。
3. 校验当前订单状态。待付款只接受未支付状态；待接单只接受已支付状态。已接单、派送中必须电话沟通，不能绕过前端直接取消。
4. 已付款的待接单订单，仅在服务端 `sky.payment.mock-enabled=true` 时执行模拟退款；同时校验支付金额为正数、支付方式为微信。关闭模拟模式时，不会将真实订单伪装成已退款。
5. 一条 UPDATE 同时写入 `status`、`pay_status`、`cancel_reason`、`cancel_time`，WHERE 还包含订单归属、原订单状态和原支付状态。更新失败或数据库异常时，整个事务回滚。
6. 成功后重新读取数据库实际保存的结果，尤其是取消时间精度，确保首次响应与重试一致。事务提交后，控制器才返回 `Result.code=1`。

待接单模拟退款成功时：

| 字段 | 变化 |
|---|---|
| `orders.status` | `2 → 6`，待接单 → 已取消 |
| `orders.pay_status` | `1 → 2`，已支付 → 已退款 |
| `orders.cancel_reason` | 用户取消待接单订单，模拟退款成功 |
| `orders.cancel_time` | 首次取消的后端时间 |
| `orders.amount` | 保留原订单金额，作为模拟全额退款金额 |
| `orders.checkout_time` | 保留原支付时间 |
| `order_detail`、`shopping_cart` | 不删除、不重复插入，不清空后来加入的购物车商品 |

本次无需修改 MySQL 表结构。退款结果通过新增 `OrderCancelVO` 返回：`id`、`status`、`payStatus`、`cancelReason`、`cancelTime`、`mockRefund`、`refundAmount`。其中 `refundAmount` 仅为模拟退款金额，不是实际银行或微信退款回执。

业务成功仍为 `code=1`，业务拒绝仍为 `code=0`，未登录沿用 HTTP `401`。

## 三、为什么区分主动取消和自动超时取消

如果支付成功与页面超时几乎同时发生，过时的自动取消请求不能把刚支付成功的订单退掉。因此：

- 支付页及详情页的自动取消均发送 `unpaidOnly=true`。
- 后端收到该参数后，只允许 `status=1/pay_status=0` 的订单取消。订单已经支付时，返回错误并让页面刷新，绝不自动切换为退款。
- 用户主动取消待接单订单时，经过取消确认后才发送普通取消请求，执行模拟退款。
- 兼容保留原 `cancelPendingOrder` 服务方法，其内部始终采用仅取消未支付订单的限制。

## 四、小程序交互

- 待付款取消前弹出确认框；待接单取消前明确提示将模拟退还的订单金额。
- 请求期间禁用取消按钮，防止重复操作，也禁止同时跳转支付。
- 只有后端返回当前订单已取消的结果，前端才更新页面。取消后立即显示已取消；已付款订单同时显示模拟退款完成及金额。
- 倒计时结束时先显示等待取消确认。若请求失败，不会假报已取消，也不会循环重试请求。
- 页面返回前台或关闭提示后重新获取订单详情，显示后端最新状态。离开页面会清理倒计时。
- 已接单/派送中按钮显示“联系商家取消”，点击后进入电话沟通提示，不发送取消请求。

商家电话已配置为用户提供的 `13671407961`：

```yaml
sky:
  shop:
    phone: ${SHOP_PHONE:13671407961}
```

可通过 `SHOP_PHONE` 环境变量覆盖。新增 `GET /user/shop/phone` 从服务端读取号码。详情页及首页电话缓存均使用服务端结果，不再在该联系流程中使用演示号码。用户点击“拨打电话”先查看号码，再点击“呼叫”才调用拨号功能；开发过程中没有实际拨号。API 参数和回调使用 [uni-app 官方拨号文档](https://uniapp.dcloud.net.cn/api/system/phone.html) 中的 `uni.makePhoneCall`。
