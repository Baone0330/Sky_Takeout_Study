# 来单与催单提醒实现说明

执行日期：2026-10-29。

## 已实现的功能

- 用户完成模拟支付后，在线管理端收到“待接单”弹窗，并在开启语音后播放来单提示音。
- 用户对已支付、待接单/已接单/派送中的自己的订单催单后，在线管理端收到“催单”弹窗并播放催单提示音。
- 消息继续使用图片约定的 JSON：`type`、`orderId`、`content`。`type=1` 是来单，`type=2` 是催单。
- 管理端与后端保持 `/ws/{sid}` 连接，有心跳、断线重连和连接销毁处理。

## 原来不生效的原因

1. 原来将来单推送单独写在 `paySuccess` 中。这个方法是微信支付回调路径，而当前模拟支付从 `payment` 直接调用 `completePayment`，不会调用 `paySuccess`，因此不会执行截图中的来单推送。
2. 原来 `paySuccess` 对已经支付的订单也会继续发送通知，重复回调会重复提醒；而且推送发生在事务提交之前，管理端可能收到尚未提交或最终回滚的订单。
3. 管理端连接地址在当前 Nginx 产物中固定为 `ws://localhost/ws/`，源码生产环境的 socket 配置又为空；没有统一的同源地址回退，也没有断线重连。
4. 原页面未处理 `audio.play()` 被浏览器拒绝的情况。首次未进行用户交互时，浏览器可能阻止声音；这与 WebSocket 是否成功收到消息是两件事。
5. 催单接口原来只按订单 ID 查询，未验证订单属于当前用户或是否仍可催单；小程序催单 Promise 失败也没有 catch。

## 支付后的来单提醒

1. 小程序请求现有支付接口。模拟模式直接执行 `completePayment`；真实微信回调调用 `paySuccess` 后也执行同一方法。
2. 只有待付款且未支付订单能首次更新为 `status=2`、`pay_status=1`，保存付款方式和支付时间。
3. 更新成功后构建消息，例如：

```json
{"type":1,"orderId":1001,"content":"订单号：test-1001"}
```

4. 使用 Spring 事务同步 `afterCommit` 在事务真正提交后推送。外层事务回滚时不发送；重复支付/回调因订单已支付而不再注册通知。
5. 通知连接失败不回滚已经提交的支付，也不会把支付结果改为失败。原有模拟退款、取消和拒单逻辑保留。

## 用户催单

1. 小程序仍调用现有 `GET /user/order/reminder/{id}`，已有登录拦截器校验用户身份。
2. 后端按订单 ID 和当前用户 ID 加锁查询，禁止催他人的订单。
3. 只允许 `pay_status=1` 且订单状态为 `2/3/4`；待付款、已完成、已取消、已退款不能催单。
4. 校验后提交事务，再发送 `type=2` 消息，`orderId` 使用数据库中的真实 ID，`content` 使用真实订单号。
5. 催单不改订单状态、不改支付状态、不扣款、不退款、不修改订单明细和购物车。
6. 小程序请求失败时显示后端错误并解除请求锁；不会假提示“催单信息已发出”。

## WebSocket 与管理端

- 后端以真实 session ID 保存连接，使用并发容器，避免多标签页或旧连接关闭误删重连后的新连接。
- 每个连接使用独立发送队列，上一条异步发送完成后再发送下一条。真实并发测试发现同时异步写可能丢消息，因此没有只用普通 HashMap 或简单并发群发。
- 发送超时为 5 秒；队列积压达到上限时清理该慢连接，避免影响其他页面或支付请求。
- 管理端每 25 秒发 `ping`，后端回 `pong`；长时间没有回复时关闭并重连。重试间隔逐步增加，最高 30 秒；网络恢复可立即尝试连接。
- Nginx 页面默认使用当前主机、当前端口的 `/ws/`，HTTPS 对应 wss。源码开发模式继续支持现有 `VUE_APP_SOCKET_URL` 配置。
- 只处理约定的 1/2 类型及有效订单 ID；忽略心跳、非法 JSON 和未知类型。内容作为普通文本显示。
- 来单消息按订单 ID 去重；真实用户再次催单仍可产生新的催单提示。
- 页面销毁/退出登录时关闭连接、取消定时器并移除语音按钮和监听器。

这是在线实时通知，管理端需要保持登录并打开页面；不提供离线消息补发。历史订单仍以数据库订单列表为准。

## 语音提醒使用方式

浏览器通常需要一次用户交互才允许播放声音。本次在管理端右下角增加“开启语音提醒”按钮：

1. 重启后端并刷新管理端。
2. 登录管理端，点击一次“开启语音提醒”；按钮显示“语音提醒：已开启”。可再次点击关闭。
3. 来单使用原 `preview.mp3`，催单使用原 `reminder.mp3`，在同一个音频元素上排队播放，避免互相重叠。
4. 即使未开启声音或浏览器拒绝播放，弹窗也正常出现；播放失败会恢复开启按钮，并捕获 Promise 拒绝。
